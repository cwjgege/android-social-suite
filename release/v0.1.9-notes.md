# Android Social Suite v0.1.9 (pre-release)

## VPN recovery fix

- Fix managed devices being skipped when Android does not expose the emulator qemu.social_owner property.
- When the guest property is absent, verify ownership using the emulator console listener PID, SDK executable path, AVD name, and installation-root tag. Conflicting guest ownership is still rejected.
- Allow the existing maintenance routine to restore the device VPN and its private ADB reverse tunnel.
- Retain existing protocol support, including VLESS and Hysteria2.

## Validation and limitations

- PowerShell syntax and live device ownership checks passed, including wrong-device and wrong-root rejection.
- A controlled VPN disconnect and removal of the device reverse tunnel were recovered by the maintenance routine in approximately four seconds on the development computer. This is not a guaranteed recovery time; periodic checks depend on the manager being open.
- Multiple new TikTok items loaded after the tunnel was restored and TikTok was restarted. No app data or account state was cleared.
- This remains a pre-release: extended playback, different computers, and every proxy protocol have not been exhaustively retested. The fix does not guarantee node or CDN performance.

## Upgrade

1. Exit all old Android Social Suite manager instances, including residual launcher processes. Normally shut down virtual phones before upgrading.
2. Download and run AndroidSocialSuite.exe below using the original installation location. Do not delete existing device or proxy directories.
3. Open the updated manager and start your phone. Keep the manager open for periodic tunnel maintenance.

Existing Android runtime files, devices, installed apps, media, and saved proxy bindings are reused in a normal in-place update. Missing components may still require a download.
